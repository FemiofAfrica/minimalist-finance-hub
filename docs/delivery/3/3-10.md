# 3-10 Robust auth & data mocks for chart E2E suites

[Back to task list](../tasks.md)

## Description

Several chart-focused Playwright suites are currently disabled via `test.skip()` because the test environment lacks reliable Supabase authentication and deterministic seeded data. This task will create robust mocking utilities (auth + data fixtures) so those suites can run green and restore full E2E coverage for PBI-3 reports.

## Requirements
1. Implement a reusable Playwright fixture (e.g. via `globalSetup` or helper) that:
   • Injects a valid Supabase `auth.token` into `localStorage` before each test.
   • Stubs Supabase network calls (`.co`, `.in`) with route fulfils returning fixture data.
2. Provide deterministic in-memory JSON fixtures for:
   • Balance trend, income vs expense, monthly totals.
   • Category insights and Smart Insights endpoints.
3. Replace the `test.skip()` guards in:
   • `test/e2e/reports-charts.spec.ts`
   • `test/e2e/chart-interactions.spec.ts`
   • `test/e2e/performance-charts.spec.ts`
   • `test/e2e/reports-insights.spec.ts`
4. Ensure all previously-skipped tests pass locally and in CI.
5. Update documentation (README or DEV_TESTING.md) explaining how to run E2E with mocks.

## Implementation Plan
1. Create `test/helpers/playwrightAuthMock.ts` to export a function that sets `addInitScript` and routes.
2. Add `playwright.global-setup.ts` to register the auth mock for all projects.
3. Add JSON fixture files in `test/fixtures/` and have route handlers read them.
4. Remove `test.skip()` lines and address any residual timing/flakiness issues.
5. Update CI config if needed to ensure preview/dev server still launches.
