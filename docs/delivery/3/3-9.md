# [3-9] Fix currency & category-type issues in Smart Insights

[Back to task list](../tasks.md)

## Description
Address two defects reported in Smart Insights:
1. "Salary" (and all income categories) should never be classified as spending. Insights such as spending spikes/drops must exclude income categories.
2. Aggregated NGN amounts are inflated (e.g., NGN 175,350,420). Root cause is likely that raw transaction amounts are stored in kobo (×100). We need to normalise amounts before insight generation.

## Requirements
1. Income categories (type === "income") must be excluded from spending-based insight types: `spending_spike`, `spending_drop`, `new_category`, `missing_category`.
2. Normalise raw transaction amounts:
   - If currency is NGN and absolute amount ≥ 10,000,000 treat value as kobo and divide by 100.
   - Apply the same logic for getCategoryTotals and getCategoryTotalsPeriod.
3. Update unit tests and integration tests to cover these cases.
4. Ensure no regression in existing tests.

## Implementation Plan
- Add `normalizeAmount` util inside `categoryAnalyticsService.ts`.
- Update amount processing in both aggregation functions.
- Update `generateChangeBasedInsights` to `continue` early for income categories.
- Extend existing unit tests or add new ones.
- Run full test suite and adjust snapshots if necessary.
