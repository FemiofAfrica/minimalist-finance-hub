## Audit Findings

| Component/Layout | Current Top-Spacing Logic | Issues Observed |
|------------------|---------------------------|-----------------|
| `PublicLayout` | Adds inline `paddingTop: isBannerVisible ? BANNER_HEIGHT : 0` and now `.safe-top` (env safe-area). | Works for banner ON/OFF but duplication with safe-top; other layouts don't share logic. |
| `Login/Signup/Reset` pages | Wrapped in `PublicLayout`. | Good after recent fix (logo visible) |
| `SupportBanner` | Fixed `top-0` height 32 px. Emits visibility change event. | Provides `BANNER_HEIGHT` constant. No problems. |
| `DashboardLayout` | Adds inline `paddingTop: isBannerVisible ? BANNER_HEIGHT : 0`. Contains its own `SupportBanner` always rendered. | Works for main content but **Sidebar** inside flex container does NOT inherit padding, so sidebar top (0) hides under banner when visible (overlap). |
| `DashboardSidebar` | Previously injected CSS to offset by banner height; that was removed. Now sits at top‐0. | Overlapped by banner (user's screenshot). Also imports `BANNER_HEIGHT` but unused after removal. |
| `PageLayout` (dashboard sub-pages) | No banner logic, just sidebar + main content. Relies on DashboardSidebar. | Same overlap problem. |
| Settings/Admin/Reports pages (any using DashboardSidebar) | Same pattern. | Overlap when banner visible on smaller viewports. |
| Any other standalone layout referencing `BANNER_HEIGHT` (search shows none) | – | – |

Summary:
* Banner height (32 px) needs to be applied consistently to **all fixed/flex root containers**, including Sidebar provider, not just main content.
* Duplication of logic (inline style in PublicLayout & DashboardLayout) should be replaced by a single helper (Task 6-2).
* Sidebar must consume same offset so it starts below banner.
